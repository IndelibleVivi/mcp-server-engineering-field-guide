## Authority 与 reachability

这里有三个必须分开的 owner：

| 边界 | Owner | 当前证据 |
|---|---|---|
| executable selection、environment delivery、child-process admission | local desktop host / parent process | [PROJECT.md](../fixtures/parent-owned-stdio/PROJECT.md#L5) 的声明；未做 host/runtime 验证 |
| 谁能够送入调用 | 持有 child stdin pipe 的 parent/OS process boundary | process-level possession/reachability model；不是 network authentication |
| method/tool/arguments 是否进入 capability | child server 的 `handle()` | 静态可见：检查 `tools/call`、`notes.lookup` 和非空 string `key` |

因此，当前调用 authority 实际上由两层共同形成：

```text
desktop host / parent
  └─ 选择并启动 executable，持有 stdin/stdout pipe
       └─ child server
            └─ method → tool name → argument validation → NOTES lookup
```

这里没有 issuer、token、audience、scope、OAuth server 或 network peer authentication。不能把 parent process 描述成 authentication protocol。更准确的说法是：**parent/OS 持有 subprocess admission 与 pipe reachability；server 内没有独立的 caller authentication 或 scope authorization。**
