## Protocol shape

- Core 是 stateless：删除 `initialize`、`notifications/initialized` 与 protocol-level `Mcp-Session-Id`。
- 每个 request 通过 `_meta` self-describing：protocol version 与 client capabilities 随 request 传递，client identity 也应在其中；server result 的 `_meta` 标识 server。
- Servers 必须实现 `server/discover`，使 client 可以在其他工作前获知 supported revisions、capabilities 与 identity。
- Servers 不发起 JSON-RPC requests，clients 不发送 JSON-RPC responses。Multi Round-Trip Requests（MRTR）通过 `InputRequiredResult` 表达输入需求，随后 client 用 `inputResponses` retry 原 request。
- 每个 result 都有 `resultType`：普通结果用 `complete`，MRTR 中间结果用 `input_required`。
- Streamable HTTP 把选定 body metadata mirror 到 required `Mcp-Method` 与 `Mcp-Name` headers。Body 是 authority；mismatch 必须被拒绝。
- General GET-based server messaging 被 `subscriptions/listen` 取代；request-scoped notifications 继续走 originating request 的 response stream。
- 删除 SSE resumability 与 `Last-Event-ID` redelivery。Response stream 断开意味着 in-flight request 丢失；retry 必须使用新的 JSON-RPC request ID。
- `CacheableResult` 覆盖的 list/read results 包含 `ttlMs` 与 `cacheScope`；list order 应 deterministic。
- Tasks 从 core 移到 `io.modelcontextprotocol/tasks`；extension framework 成为 optional protocol families 的显式路径。

## Stateless 不等于 effect-free

删除 transport sessions 意味着任何 request 都能落在任意 compatible instance；它没有删除 application state、durable jobs、authorization subjects 或 idempotency 需求。

若需要 cross-call state，应 mint 一个显式 server-owned handle，并把它作为普通 tool data 传递。定义：

- 谁可以持有与使用 handle；
- 它是 opaque 还是 model-readable；
- expiry 与 revocation；
- storage 与 concurrency ownership；
- retry 与 duplicate-effect semantics。

不要换一个 header 名字重新发明 implicit transport session。

## Streamable HTTP obligations

- 每个 request 或 notification 都通过 HTTP POST 到 MCP endpoint。
- 在 framework 允许时，于 expensive body work 前检查 revision-specific protocol metadata 与 routing headers。
- Dispatch 前比较 mirrored `Mcp-Method` / `Mcp-Name` 与 decoded body；不能只根据 attacker-controlled headers 授权。
- Request body `_meta` 是 authority；不一致时返回 revision-defined mismatch error。
- 响应为 JSON 或 request-scoped SSE stream。在本 binding 下，HTTP response stream 断开表示该 request 被 cancellation/abandonment。
- 不要继续把 `Mcp-Session-Id`、GET resumability、`Last-Event-ID` 或已删除的 initialize lifecycle 声称为 active features。
- 只有真正拥有且限制 change-notification streams 时才实现 `subscriptions/listen`。

## Implementation consequences

1. Dispatch 不能依赖 connection-local initialization state；每个 request 都验证 protocol version 与 client capabilities。
2. `server/discover` 必须 truthful、足够廉价，并具有足以支持 compatibility decision 的 deterministic behavior。
3. Header-based routing 是 optimization 与 policy input，不是 body validation 的替代品。Gateway 与 application 需要共享 mismatch contract。
4. MRTR retry 需要显式 operation identity。若返回 `input_required` 前可能已开始工作，应说明 retry 是 resume 还是 restart。
5. Result serialization 必须总是包含正确 `resultType`；对 earlier server 缺失该字段的 compatibility handling 属于 client 侧责任。
6. Cache metadata 同时是 disclosure 与 freshness decision。Personalized 或 authority-sensitive catalog 不能使用 `cacheScope: public`。
7. Deprecated Roots、Sampling、Logging、legacy HTTP+SSE 与 Dynamic Client Registration 不应进入新设计，除非存在受控 compatibility 理由。

## Revision-bound test obligations

- 任意 valid request 无需 prior initialize exchange，也能在 fresh instance 执行。
- Missing、malformed 或 unsupported per-request protocol metadata 返回 revision-defined error。
- `server/discover` 只声明实际实现的 revisions、capabilities、extensions 与 identity。
- 按 specification 要求 `Mcp-Method` 与 `Mcp-Name`，并与 body 比较；mismatch 绝不能进入 capability execution。
- 拒绝 server-originated JSON-RPC request shape 与 client-originated JSON-RPC response shape。
- 每个 result 都有 valid `resultType`；MRTR input request 与 retry 保持 operation semantics。
- Response-stream 断开后的 retry 使用新 request ID，且不会静默重复 non-idempotent effect。
- Cacheable results 有合法 `ttlMs` 与 `cacheScope`；lists deterministic。
- Removed sessions、initialize flow、GET stream 与 SSE resumption 不得作为 active compatibility theater 残留。

## Migration boundary from 2025-11-25

把 migration 当作 architecture replacement：

1. 从所选 active path 删除 lifecycle gates 与 session headers；
2. 加入 per-request metadata validation 与 `server/discover`；
3. 用 MRTR 替代 server-initiated request flows；
4. 用 request-scoped streams 或 `subscriptions/listen` 替代 GET/resumability design；
5. 加入 routing-header/body consistency checks；
6. 加入 required result 与 caching metadata；
7. 把 task support 移到 official extension；
8. 审查 deprecated features，删除 unsupported capability claims。

若必须 backward compatible，应隔离成有测试、带显式 revision decision 的 adapter；不要让 stateful 与 stateless semantics 变成散落在 capability core 各处的模糊 conditionals。

## Known unknowns

- 即使 Tier 1 SDK 声称 support，host 与 SDK adoption 仍可能落后于 specification。
- 可用于 header validation 的确切 pre-dispatch hooks 取决于 HTTP framework 与 proxy chain。
- MRTR、extensions 与 `subscriptions/listen` 必须在目标 host 实测，不能从 spec publication 直接推定。
- OAuth 与 host-integration guidance 独立演进；使用带日期的 [integration profile](integration-guidance-2026-08-15.zh-CN.md)。
