# MCP profile：2025-11-25

本 profile 适用于明确选择 MCP revision `2025-11-25` 的 implementation。它保留 stateful lifecycle 时代的架构，同时纳入 2025 年 11 月的 feature 与 security 变化。

## Protocol shape

- `initialize` / `notifications/initialized` lifecycle 与 negotiated protocol version 仍是 authority。
- Streamable HTTP 仍允许通过 `MCP-Session-Id` 建立 optional protocol sessions，也允许 request-scoped SSE response、GET SSE channel，以及基于 `Last-Event-ID` 的 resumability。
- 对 present invalid `Origin`，transport 明确要求返回 HTTP `403 Forbidden`。
- 支持 polling SSE：server 可以关闭 connection 而不终止 logical stream；event IDs 与 retry behavior 承担 resumption contract。
- URL-mode elicitation、sampling 中的 tool use、OAuth Client ID Metadata Documents、incremental scope consent、icons 与 experimental tasks 进入 feature surface。
- JSON Schema 2020-12 成为 MCP schema definitions 的默认 dialect。
- Tool call 的 input validation failure 属于 tool execution error，便于 model 修正 arguments；它不自动属于 protocol error。

## Streamable HTTP obligations

- POST 与 GET 共用一个 MCP endpoint。
- 验证 `Origin`；若 present 且 invalid，返回 HTTP 403。Missing `Origin` 不等于 present invalid value，应另行定义 policy。
- 要求正确的 `Accept` negotiation；每个 POST 只能有一个 JSON-RPC message。
- 接受 notification 或 response 时返回无 body 的 HTTP 202。
- Request 响应为 JSON 或 request-scoped SSE stream。
- 若实现 polling 或 resumability，event ID 必须识别 originating stream，并通过带 `Last-Event-ID` 的 GET 恢复。
- 若发出 `MCP-Session-Id`，必须拥有其 generation、secure handling、lookup、expiry、termination 与 404 semantics。
- 后续 requests 发送 `MCP-Protocol-Version`；unsupported version 必须被拒绝。

## Implementation consequences

1. Transport session state 与 application operation state 分开。Session ID 不能替代 idempotency key 或 authorization subject。
2. 把 polling SSE 当作 stateful feature。若声称 resumability，关闭 TCP connection 不得静默丢失 logical stream。
3. stdio 使用 `stderr` 记录 logs；`stdout` 只能包含有效 MCP messages。
4. 按 JSON Schema 2020-12 假设验证 schemas，并给 recursive/composed schema work 设置边界。
5. URL elicitation 与 experimental tasks 必须受 explicit capability declaration 和 host-compatibility evidence 约束。
6. Tool annotations、icons、descriptions 与 validation-error classification 都是 host 和 model 可观察 behavior。

## Revision-bound test obligations

- Stateful lifecycle ordering 与 re-initialization tests。
- Present disallowed `Origin` 明确返回 HTTP 403；允许 cross-origin 时只精确 echo allowlist value。
- 不接受 JSON-RPC batch。
- Notification/response POST 返回无 body 的 HTTP 202。
- Session 要么不发出，要么具备 secure uniqueness、request validation、expiry、termination 与 404 behavior。
- Polling SSE reconnection 保持 stream identity、遵守 retry timing，且不会 replay 其他 stream 的 messages。
- Tool input validation failures 使用本 revision 预期的 tool-result error channel。
- Experimental task、URL elicitation 与 sampling-tool capabilities 除非完整实现并在目标 host 验证，否则不应声明。

## Migration boundary from 2025-06-18

不能因为 lifecycle shape 相似就推断 support。Explicit invalid-Origin 403 behavior、polling SSE rules、JSON Schema dialect、URL elicitation、sampling tools、registration guidance 与 tasks 都需要独立 implementation 和 tests。

## Migration boundary to 2026-07-28

下一 revision 删除了本 profile 所依赖的 lifecycle 与 session architecture；同时删除 GET-based general server streams 与 SSE resumability，用 Multi Round-Trip Requests 取代 server-initiated requests，要求 request `_meta` 携带 metadata，加入 `server/discover` 与 HTTP routing headers，并把 tasks 移入 extension。见 [2026-07-28 profile](mcp-2026-07-28.zh-CN.md)。

Compatibility 应由显式 adapter 或 negotiated mode 承担。选择 stateless revision 后，不要让旧 session checks 半残留在 active path。

## Known unknowns

- Host 对 polling SSE、URL elicitation、experimental tasks 与 Client ID Metadata Documents 的支持各不相同。
- Framework 可能在 application dispatch 前生成或消费 session/version headers；必须检查真实 hook order。
- 只看 application code 无法证明 authorization topology。
- Current ecosystem recommendations 可能已在本 profile 的 assessment date 后变化。
